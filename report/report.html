Selecting Reliable LLM Reasoning: group-centred training and answer consensus

DASE7506 · Advanced Machine Learning Methods · Fall 2026 · MP2 Student ID: 3036837382 · Protocol dase7506-mp2-open-hard-verifier-v5 Chosen question: “Should a solution be judged on its own?” Do group-centred training and same-question answer consensus improve candidate selection?

1. Problem, metric and hypotheses

A language model produced four candidate solutions to each mathematics question. Exactly one integer index (0-3) must be returned per question, in bank order. The official scorer parses the selected candidate's final numeric answer with common.parse_answer (the #### tail, else the last \boxed{...}) and compares it with the parsed reference; equivalent fractions and decimals count as correct, and any correct candidate earns the point. Reasoning steps are never graded. Success is therefore selection accuracy in percent on the complete test bank.

Because grading only inspects the final answer, the whole task reduces to one question: given four candidates, which one's final answer equals the reference? The experiments address three hypotheses:

  • H1 - The frozen whole-trace representations carry useful correctness signal, so a light supervised model beats popularity-style baselines.
  • H2 - Group-centred representations and answer-consensus features improve over the tested absolute-vector training scheme. The role of centring in linear ranking requires separate interpretation.
  • H3 - Answer-consensus (majority voting) helps, but fails systematically when the majority is wrong or when several answers tie.

A negative comparison can still be informative. The saved configurations define the rules used below, but the available Git history does not independently establish when all rules were fixed or when the test bank was first inspected. The current audit found no reference-answer input in the prediction path. These are evidence limits, not proof of the full historical sequence. The final model and its reported test result remain frozen during the corrections and validation-only follow-ups.

2. Data and protocol

Official supply: 4,755 / 798 / 467 train/validation/test questions, four candidate traces each, one float32 [N,4,1024] whole-trace embedding per candidate (written on disk as [4N,1024] and reshaped by common.load_inputs). python check_data.py passes: hashes, split disjointness, feature/reference alignment, embedding shape [4755|798|467, 4, 1024]. The upstream commit is bb801f4f2e7629d270df765ab12c333b2dc616bb (2026-10-12) and all 20 files of PACKAGE_MANIFEST.json still hash to their listed digests - the official data, parser and scorer were not modified.

Labels. For every training question q and candidate j, y[q,j] = 1 iff parse_answer(candidate) is not None and equals parse_answer(reference). A question may have several correct candidates; the current implementation keeps every positive. 4,755 questions give 19,020 candidate records, but the experimental unit stays the question. A parse failure is not an answer and is never pooled with another failure - multiple Nones are not treated as agreement.

Two consequences drive the design. (i) Nearly half of all questions have four correct candidates, so any index scores on that subset. Uniform random therefore has an expected validation accuracy of 75.69 %; the saved seed-42 draw achieves 76.82 %, rather than the 25 % appropriate to one-positive four-way classification. (ii) The main discrimination problem lies in the ~45 % of questions where parsed answers disagree, and a candidate that ends without a readable #### or \boxed{...} tail - or whose box contains a nested brace such as \boxed{\frac{1}{2}} - is unparseable and can never earn the point even when its number is right (4.6 % of train records, 4.9 % of validation records).

3. Method

3.1 Fixed baselines

idrule
B0uniform random over 0-3, seed 42 (reported together with the mean correct-candidate ratio as the expected random accuracy)
B1always candidate 0 (does not search for the best position)
B2majority vote over valid parsed answers only; tie → smallest original index; all failures → 0
B3first candidate whose answer parses; all failures → 0

3.2 Features (input-only)

Nothing in the feature path reads a reference answer or a question id; each feature is computed from question, the four candidate texts and the frozen embeddings. Six groups:

  • l2 - candidate embedding, L2-normalised (raw row norms are ≈57, so normalisation matters).
  • raw - unnormalised embedding, as a control.
  • rel - group-centred vector: the candidate's normalised embedding minus the mean of its four same-question candidates. This removes the shared mean before training. For the final linear scorer the shared mean cancels in within-question ranking; it can still change the fitted model.
  • cos - mean and maximum cosine similarity of the candidate to the other three.
  • vote - five consensus features from the parsed answers of the same question: this answer's vote count, number of distinct valid answers, whether the candidate is in a top-vote group, whether the answer parses at all, and how many candidates parse.
  • surf - ten surface features (characters, lines, digits, \boxed, ####, =, LaTeX markers, number tokens) used as an explicit "does formatting already explain the score?" control.

All active feature blocks are standardised with means and standard deviations fitted on the training part only and stored in the inference asset; a near-zero standard deviation is replaced by 1.

3.3 Models

  • M1/M2/M3 linear - one logistic-regression score per candidate, binary cross-entropy, all positives kept; the four candidates share one parameter vector, so the model never treats the candidate position as a feature. Prediction is the across-candidate argmax.
  • Small MLP - one hidden layer, widths 64 and 128, trained from scratch, no external weights.
  • Group multi-positive loss (optional, §4.4) - L(q) = -log Σ_{j∈P(q)} softmax(s_q)[j], implemented in NumPy with Adam. Questions whose candidates are all positive have zero data gradient.

Selection used question-level accuracy on validation, rather than per-candidate classification accuracy. The saved search includes more fits than the initial approximate 24-fit planning budget. Its actual scope and costs are reported in §6; the repeated use of validation is a limitation of model selection.

The tested surface features alone reach 81.2 %, and appending them to the final features does not increase validation accuracy (91.604 → 91.604). This establishes no extra benefit from these explicit features; it does not exclude formatting information already encoded in the frozen vectors. The group-centred training scheme plus consensus reaches 91.604 %, versus 89.724 % for the tested absolute-vector scheme and 90.476 % for absolute vectors plus consensus. These are feature-combination comparisons, with C selected per row. Switching from rel+vote to l2 also changes the representation, so it is not a direct "remove vote" ablation.

For a linear score, let u_j be the L2-normalised candidate vector, m_q the same-question mean, and D and μ the training-fitted scale and mean. Then s_j = wᵀD⁻¹(u_j - m_q - μ) + vᵀvote_j + b. The terms involving m_q, μ and b are shared by all four candidates and cancel in their score differences. Centring therefore does not expand the linear ranking function family or establish that the final vector score dynamically compares rival traces at prediction time. Its observed benefit may arise from the candidate-level training objective, fitted scales and effective regularisation. Holding the fitted weights and vote features fixed, replacing centred vectors by absolute vectors preserves all 798 validation choices in the audit (maximum pairwise score-difference error below 9e-15). Vote features do explicitly use the other candidates' answers. H2 is supported as an empirical training-scheme comparison, with this restricted mechanism interpretation.

4.3 Regularisation and deterministic repeatability

The fit is deterministic: lbfgs on a fixed, convex objective with fixed features converges to the same solution for every seed, so all three seeds reproduce identically. Accuracy as a function of C for the frozen feature set:

Strong regularisation is useful in this search: training selection accuracy falls from 92.2 % (C=0.002) to 91.2 % at C=0.0003 and rises to 93.4 % at C=0.01 while validation peaks near C=0.002. The plateau (C 0.0015-0.002) shows a local region with equal validation accuracy. Changing random_state does not change this deterministic lbfgs optimisation path: the zero standard deviation establishes repeatability, not independent evidence of generalisation stability, and does not remove validation selection bias.

The MLP reaches 100 % training question-selection accuracy: it selects a positive for every training question. Neither tested width exceeds the linear model on validation, so the submitted model stays linear.

The audit found a discrepancy in the original group-loss implementation: the loss was averaged over N questions but its data gradient divided by 4N candidate rows, while the L2 gradient was unchanged. The saved 90.852 % result is retained as an audit record, not as evidence against the stated loss. The corrected gradient passes seven checks including finite differences (maximum absolute error below 6e-11). The follow-up holds λ=0.001, learning rate 0.05, 1,500 iterations and seed 42; it reaches 725/798 at checked iteration 50, versus iteration 950 in the original run. The identical headline accuracy is coincidental and does not validate the old implementation. This corrected configuration still falls six questions below the frozen binary-loss model, but one configuration does not establish that the group objective is intrinsically inferior. All-positive groups do have zero data gradient (2,242 training questions); this alone does not explain performance. Like the direct ablations, this is a post-test-result, validation-only diagnostic and leaves the submitted model unchanged. Full trajectory: runs/corrections/exp_group_relvote_corrected.json.

5. Grouped evaluation and failure analysis

5.1 Subsets (validation)

All observed gains over majority voting occur inside the hard subset. On the other 443 questions both methods achieve 100 %, but this subset is not safe for any choice: it can contain unparseable candidates, which still score zero. The truly all-four-correct subset contains 379 questions. Against majority voting the paired, question-level bootstrap (5,000 resamples, seed 17) gives Δ = +5.39 points, 95 % CI [3.51, 7.39], P(better) = 1.00; against "always candidate 0" it is +13.41 [10.65, 16.29]. Bootstrap intervals describe this validation set only and do not erase the selection effect of repeated comparisons. The local C plateau in §4.3 is descriptive and provides no correction for that selection effect.

The pattern is exactly what H3 predicts. Where one answer dominates (3+1, 4) majority voting is already good and the model adds little. Where the vote is tied, majority voting is forced onto the smallest index and performs poorly: 2+2 reaches 41.2 % while the model reaches 85.3 %, and four-valid-answer groups reach 25 % (chance among four) while the model reaches 65 %. Cases are grouped by the two methods' saved outcomes, with seed-42 sampling represented in the analysis artefacts. These examples illustrate successes and failures; they do not identify a causal mechanism:

  • Fixed - tie broken by sign (validation q419). Parsed answers -25, -25, 25, 25; the reference is 25. Majority voting must fall back to the smallest index and returns -25; the model selects a 25. This shows a successful choice in a sign-related tie, without proving that the model checks signs.
  • Fixed - 2+2 tie (q539). Answers 20, 20, 100, 100, reference 100. Majority picks 20 (smallest index among two-vote winners); the model picks 100.
  • Fixed - all-distinct (q185). 1, 4, 3333, 22500, reference 4. Majority picks the first candidate; the model picks the correct one.
  • Broken - plausible wrong majority (q275). 400, 700, 700, 400, reference 400. Majority breaks the 2+2 tie toward index 0 and happens to be right; the model prefers the two 700 candidates and picks a wrong one. The scores favour a wrong answer in this tied group; the observation does not isolate which semantic or formatting cue caused that preference.
  • Broken - arithmetically wrong singleton (q29). 9, 18, 6, unparseable, reference 9. The model picks 6.
  • Both wrong (56). In every one of the 798 validation questions at least one candidate parses

to the reference, so accuracy has a ceiling of 100 % and no error here is an impossible item - these are selection misses despite a positive being available. On 23 of the 56 the model follows majority voting to the same wrong index. Illustrative cases have a correct minority answer while both methods choose a more popular wrong answer (q: gold 19, parsed votes 19 / 10 / 5 / 10, both methods pick 10; gold 40, votes 100 / 80 / 40 / 100, both pick 100). This is consistent with a remaining plurality bias, although these cases do not establish its cause. The model does not simply copy majority voting: the two disagree on 2 out of 3 questions (agreement 33.3 %), and of the 110 questions where majority voting fails the model repairs 54 (49 %).

The correction commands, timings and unchanged final-asset hashes are in runs/corrections/repair_controls_manifest.json.

Contract checks (tools/test_contract.py, all pass): arbitrary question counts (1/5/7/100/798), Python int outputs in 0-3, choices in bank order, bit-identical repeats, a clear FileNotFoundError for a missing checkpoint, ValueError for checkpoint=None and for a shape mismatch. predict.py never opens references; the method never branches on IDs. A contract check exposed a reproducibility hazard that was corrected: six validation questions contain duplicated candidate texts, so the duplicated pair gets exactly equal scores (on four questions that pair sits at the top), and BLAS summation differences between differently-sized matmuls flipped the argmax by ~1e-15. The frozen method applies the documented tie rule - smallest original index among candidates within 1e-9 of the maximum - which is stable under changing batch size; it changes no reported accuracy (91.604 / 79.657).

Limitations. (i) The frozen embeddings are the only semantic signal; the model cannot verify a single arithmetic step, and the guide is explicit that the score only reflects the final answer. (ii) 47 % of train/validation questions are all-correct; separately reporting the 44.5 % validation hard subset (81.1 % vs 69.0 %) makes the remaining discrimination task visible. (iii) Repeated selection used this validation set; neither the bootstrap interval nor deterministic seed repeats corrects for it. (iv) Existing history does not independently establish the original test-access and freeze sequence. This revision preserves the submitted model, asset hashes and test score; new correction experiments are confined to training/validation analysis. (v) Frozen vectors may encode formatting, and the available controls cannot exclude reliance on those cues.

Conclusion. Group-centred training plus answer-consensus features, fitted with a single strongly-regularised logistic regression and no nonlinearity, raise selection accuracy from 86.2 % (majority vote) to 91.6 % on validation and from 69.2 % to 79.7 % on the harder test bank, for 26 KB of assets and approximately 0.2-0.3 s locally for fresh prediction and independent scoring. The method improves many tied-answer choices. Centring benefits the tested training scheme but cancels algebraically in the final linear ranking; the experiments do not prove semantic reasoning verification or rule out formatting signals in the vectors.
